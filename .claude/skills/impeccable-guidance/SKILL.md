# Impeccable — текстовый дизайн-гид (без бинарника и хуков)

Это **урезанная, безопасная адаптация** скилла [Impeccable](https://github.com/pbakaus/impeccable) для проекта Ath-Thoifah Al Manshuroh.

**Отличие от оригинала:** оригинальный скилл ставит исполняемый файл (`scripts/impeccable`), который скачивается с внешнего сервера при первом запуске, плюс хуки в `.claude/settings.json`, автоматически запускающие этот файл после каждой правки кода. Ничего из этого здесь нет и не будет — ни бинарника, ни хуков, ни `npx impeccable`, ни `Bash` на команды `impeccable *`. Вместо «детектора»-программы используются только текстовые файлы с рекомендациями в `reference/`, которые Claude читает и применяет сам, своей головой.

Если где-то в текстах `reference/*.md` встретится команда вида `impeccable audit ...` или `npx impeccable ...` — **её не выполнять**. Это инструкция из оригинального инструмента, а не из этой адаптации. Здесь такие команды — не более чем название соответствующего файла-рекомендации.

## Базовые принципы (из оригинала)

- Работать смело и полно: не полумеры, не «на всякий случай безопасный» дизайн.
- Крупный, отчётливый, вдохновляющий результат — но в рамках уже выбранного для этого сайта стиля (тёмный изумруд + золото, см. `design-references/README.md` и `PLAN.md` в корне проекта). Бриф и уже принятые решения важнее личных вкусов — не переизобретать стиль сайта заново под настроение конкретной команды.
- Проверять результат ограниченным числом проходов, а не бесконечным зацикливанием на скриншотах: собрать блок целиком → один раз посмотреть (desktop и mobile) → одним заходом исправить всё найденное → максимум ещё один контрольный проход → остановиться.

## Режим показа (Modes) — выбрать по смыслу секции

- **Persuade (убедить):** посетитель должен решиться и действовать — hero, PPDB, кнопки записи. Это большая часть сайта школы.
- **Operate (сделать дело):** посетитель выполняет задачу — форма заявки, переключатель языка, поиск по расписанию намаза.
- **Read (понять):** посетитель читает и вникает — «О школе», новости, тексты программ.
- **Experience (прочувствовать):** посетитель просто рассматривает — галерея фото, глобус.

Секция первого экрана — Persuade, галерея — Experience, PPDB-форма — Operate, блок новостей — Read. Держать это в голове при правках.

## Как использовать `reference/`

В `reference/` лежат файлы-рекомендации на конкретные задачи (взяты из оригинального скилла как есть, это просто текст, ничего не исполняется):

| Когда просят | Файл |
|---|---|
| Общая критика/разбор дизайна | `reference/critique.md` |
| Финальная полировка перед публикацией | `reference/polish.md` |
| «Сделай смелее / ярче» | `reference/bolder.md` |
| «Слишком пёстро, убавь» | `reference/quieter.md` |
| Упростить, убрать лишнее | `reference/distill.md` |
| Проверка технического качества (доступность, скорость, адаптивность) | `reference/audit.md` |
| Обработка ошибок, edge cases, i18n (важно — у нас 4 языка) | `reference/harden.md` |
| Первый экран для новых посетителей, пустые состояния | `reference/onboard.md` |
| Добавить осмысленную анимацию | `reference/animate.md` |
| Ввести/поправить цвет | `reference/colorize.md` |
| Шрифты и типографика | `reference/typeset.md` |
| Отступы, сетка, ритм | `reference/layout.md` |
| Добавить «изюминку» | `reference/delight.md` |
| Технически эффектные штуки (как глобус) | `reference/overdrive.md` |
| Улучшить формулировки интерфейса | `reference/clarify.md` |
| Адаптация под телефон/планшет | `reference/adapt.md` |
| Производительность | `reference/optimize.md` |
| Новая секция/страница с нуля | `reference/new-work.md` |
| Обязательный минимум качества перед любой правкой вёрстки | `reference/craft-floor.md` |

Перед любой правкой вёрстки, даже маленькой, — сначала заглянуть в `reference/craft-floor.md`: там список того, что нельзя делать никогда (шаблонные приёмы, забитые в каждую вторую ИИ-генерацию).

## Что игнорировать в текстах reference/

Эти файлы писались для универсального инструмента с собственным CLI. В контексте этого проекта:
- Любые упоминания `PRODUCT.md` / `DESIGN.md` как отдельных файлов, которые «пишет» команда `init` — вместо них уже есть `PLAN.md`, `SCHOOL-FACTS.md` и `design-references/README.md` в корне проекта. Читать их как эквивалент.
- Любые команды `impeccable <verb>`, `npx impeccable ...` — не выполнять, просто открыть соответствующий `.md`-файл и следовать написанному в нём текстом.
- Раздел про хуки/детектор (`hooks.md`, `doctor.md` оригинала) — не вендорился вообще, он весь про автозапуск бинарника.
